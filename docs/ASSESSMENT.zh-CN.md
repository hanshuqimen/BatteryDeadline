# 提示词评估与实施决定

这份规格适合作为 Windows 电池截止时间控制器的工程需求。功耗预算 `可用 Wh / 剩余小时` 正确，分层遥测、缓慢反馈、能力检测和先记日志再修改是必要设计。Tauri 2、Rust、React 和 SQLite 可以实现第一版完整 MVP。

它不能直接作为“成熟产品已验证”的证明。成熟度还需要不同厂商、Modern Standby、外接显示器、系统策略和电池老化设备的实测。本文所称第一版是可安装、具备真实系统适配和自动化验收的 v0.1；不承诺确定续航或未经测量的 CPU/内存预算。

## 必须澄清的边界

- **预测终点**：规格同时出现“电池耗尽时间”和“保留 10%”。界面 Expected until 使用达到预留电量的时间；不会把耗到 0% 的时间当作达标时间。所有示例节电量仅是示例。
- **硬件单位**：相对容量不能当作 mWh。多电池必须完整聚合；部分设备缺失时降级，不能把一个电池的容量当作整机容量。
- **控制能力**：亮度 WMI 通常针对内置面板；刷新率只使用当前几何和色深下枚举的合法频率；电源计划是否生效由驱动和系统策略决定，API 成功不代表一定节电。
- **恢复语义**：系统设置修改前 SQLite FULL 同步写入原值、目标值和设备标识。修改后验证。失败保留恢复记录，阻止再次启动。恢复尊重后来手动修改，设备暂时消失则保留待恢复记录。
- **崩溃**：无法保证进程被强杀后立即执行代码。保证下次同模式启动自动恢复；未重启前设置可能仍保持。正常退出、停止、插电、截止时间和长采样间隔会触发恢复。
- **睡眠/时钟变化**：检测采样时间断层，恢复并重新预热估计器；不用睡眠前功耗预测醒来后的负载。
- **调节幅度**：一次一个变量，亮度每次最多 10 个百分点，合法刷新率逐级切换，CPU 政策最多 10 个百分点。采用 +8 到 +22 分钟死区、持续不足判断、冷却和缓慢放宽。
- **功率未知**：Wh 斜率和百分比斜率为降级预测。百分比预测不输出虚假的瓦数；不可靠读数不触发激进动作。
- **省电统计**：只能记录观察到的功耗差异，不能证明因果。无可信反事实时历史的节省 Wh 留空。
- **EcoQoS**：按 §41 允许推迟到 v0.2；v0.1 不修改任何进程，也不提供无效开关。
- **性能指标**：CPU <0.5% 是需要实测的目标。1 Hz 电池采样、20 秒能力检查、不可见界面停止更新、有限日志和数据留存降低自身消耗。
- **范围**：用户本次明确要求完整项目，优先于附文 §56“首轮仅做 Phase 0–3”。因此继续完成全部 MVP 和开源发布。

## 验收方式

纯 Rust 测试覆盖预算、预留、平滑、缺失功率、死区、控制节奏、插电、截止、手动修改与持久恢复。模拟器使用与生产相同的控制和日志实现，只替换硬件适配器。真实电池探针只读，作为本机遥测验证。Windows 安装包、前端交互、CI 与跨设备手测分别记录，不能互相替代。
